# Aavanam

**AI Document Extraction Platform** — extract structured data from any document.

Upload a PDF, PNG, or JPG → the platform parses (or OCRs) the text, calls an
LLM with your template's schema, validates the result, and returns
schema-valid JSON with optional CSV/XLSX exports. Multi-invoice PDFs are
auto-detected and split into per-invoice jobs. Templates can be built
visually or auto-generated by uploading a sample document.

> **Status**: MVP vertical slice (Day 1 + Day 2 complete).

## Live preview

The app runs on a Z.ai preview URL: `https://preview-<bot-id>.space-z.ai/`.

Open it in a browser to:
- **Extract tab** — upload a PDF/PNG/JPG, pick a template, get structured JSON back
- **Template tab** — edit field schemas, use "✨ Analyse sample → suggest fields" to auto-build a template from a sample
- **History tab** — view past jobs, download JSON/CSV exports

## Two starter templates seeded

1. **Invoice (basic)** — 11 fields (invoice_number, dates, vendor, line_items). Western-style invoice.
2. **Indian GST Invoice** — 26 fields + 11 sub-fields for line items. Includes GSTIN, PAN, contract number, milestone, reverse charge, per-line material/service/GST split. Tested on real BioGas Plant invoices (Renergy Dynamics Pvt Ltd → Refex CBG SPV).

## Built on

- **Frontend**: Next.js 16 (App Router) + React 19 + TypeScript + Tailwind 4 + shadcn/ui (48 components)
- **Backend**: Next.js API routes (FastAPI would be a separate Python service per the BRD — see `docs/BRD.md` §4)
- **Database**: Prisma ORM + SQLite (structurally identical to PostgreSQL — swap when deploying to GCP)
- **PDF parsing**: `unpdf` (pure-JS, no worker needed)
- **OCR**: System Tesseract 5 via `child_process` (`--psm 4` for column-aware)
- **LLM**: Z.ai GLM-4 via `z-ai-web-dev-sdk` (auto-splits large templates into 2 parallel calls to avoid context-window issues)
- **Validation**: Custom schema validator (missing required fields, type mismatches, invalid dates/emails/phones, line_item sub-field validation)
- **Exports**: JSON + CSV (XLSX deferred to Phase 5 — see `docs/PLAN.md`)

## Architecture (provider-neutral adapters)

Per the BRD §4 — keep all parsers and AI providers replaceable. The codebase
has clean adapter interfaces so swapping any one of them requires no changes
to the rest of the app:

```
src/lib/ocr/index.ts                — OcrAdapter (TesseractAdapter, PaddleAdapter stub)
src/lib/extraction/extractor.ts     — LlmAdapter  (ZaiLlmAdapter, OpenAiLlmAdapter ready to drop in)
src/lib/pdf/extract.ts              — PDF parser adapter
src/lib/extraction/multi-invoice.ts — invoice splitter adapter
```

### How to swap LLM provider at test time

In `src/lib/extraction/extractor.ts` change one line:

```ts
// Before (default):
let activeAdapter: LlmAdapter = new ZaiLlmAdapter()

// After (with sponsor's OpenAI key):
let activeAdapter: LlmAdapter = new OpenAiLlmAdapter('sk-...')
```

OpenAI gpt-4o-mini is ~5–10× faster than Z.ai GLM-4 on the same invoices.

### How to enable PaddleOCR (when deployed to a server with Python)

In `src/lib/ocr/index.ts`, fill in the body of `PaddleAdapter.recognize()` to
call a Python sidecar service via `fetch()`. The engine comparison UI panel
will start showing PaddleOCR results alongside Tesseract automatically — no
frontend changes needed.

## How to run locally

```bash
# Install deps
bun install

# Push Prisma schema to SQLite
bun run db:push

# Seed bundled templates (Invoice basic + Indian GST Invoice)
curl -X PUT http://localhost:3000/api/templates

# Start dev server (auto-runs in Z.ai preview env)
bun run dev
```
